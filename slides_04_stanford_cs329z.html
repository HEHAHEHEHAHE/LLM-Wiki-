核心命題

迷思與真相：從 LLM 到自主代理系統

迷思：LLM 本身就是 Agent

  • 無狀態文字轉換器：傳統 LLM 是單向自回歸輸出，Token 生成結束即終止，無持續狀態維護能力。
  • 閉合記憶限制：純 Prompt 推論受限於靜態權重，在多跳事實推導中幻覺率高達 56%。
  • 無法改變現實：無外部致動器（Actuator），無法感知環境反饋或修正錯誤。

真相：Agent 是微型認知作業系統

  • 閉環控制迴圈：建立 Perception $\to$ Brain/Planning $\to$ Action $\to$ Environment 狀態機。
  • 認知架構賦能：結合工作記憶、情境記憶、工具調用與反思引擎，將客觀事實幻覺壓制為 0%。
  • 測試時計算躍升：透過後台多輪取樣與環境反思，實現超越模型世代的任務解決力。

理論基石

代理的經典定義與現代實體轉化

Stuart Russell & Peter Norvig 經典定義：
「代理（Agent）是任何能夠透過感測器（Sensors）感知其所處環境，並透過致動器（Actuators）對該環境採取行動的實體。」

感知端 (Sensors / Perception)

  • 文字與上下文：即時對話歷史、系統提示詞、指令意圖。
  • 多模態與環境狀態：終端標準輸出、代碼執行錯誤報錯、網頁 DOM 節點、外部 API 返回值。

致動端 (Actuators / Actions)

  • 作業系統控制：檔案讀寫（`read_file`, `write_file`）、終端指令運行（Bash / Sandbox）。
  • 外部服務調用：Web 搜尋引擎、資料庫查詢、第三方 RESTful API。

技術演進

代理演進史：三代架構之跨越

第一代：符號專家系統

1970s - 1990s

  • 機制：人工手寫規則（If-Else 規則引擎）。
  • 瓶頸：缺乏泛化能力，面對開放世界產生組合爆炸。
  • 特徵：純粹符號推理，無自主學習能力。

第二代：強化學習代理

2010s - 2020s

  • 機制：馬可夫決策過程（MDP, AlphaGo, DQN）。
  • 瓶頸：樣本效率極低，僅適用於封閉規則遊戲。
  • 特徵：缺乏常識推理與通用語言理解。

第三代：語言認知代理

2022 - 現在

  • 機制：大模型大腦 + ReAct 閉環 + 外部工具。
  • 突破：具備常識推理、自我反思與開放環境互動。
  • 特徵：MRKL、ReAct、SWE-agent 引領工業落地。

架構設計

現代代理認知架構 (The Agent Triad)

1. 大腦：推理與規劃

  • 子目標分解：將複雜工程任務拆解為微小可執行單元。
  • ReAct 思考迴圈：Thought $\to$ Action $\to$ Observation 循環交織。
  • 自我反思 (Reflexion)：根據環境報錯進行動態調優與回溯。

2. 階層式記憶系統

  • 工作記憶 (Working)：即時上下文視窗，成本高且長度受限。
  • 情境記憶 (Episodic)：儲存歷史執行軌跡與使用者互動體驗。
  • 語意記憶 (Semantic)：外部向量資料庫，儲存世界知識與規則庫。

3. 工具與環境介面

  • 強型別規格 (Schema)：JSON Schema 與約束解碼。
  • 安全隔離沙盒：容器化隔離環境，杜絕代碼注入危險。
  • 實體狀態變更：落實寫入檔案、查詢資料庫與網路檢索。

破除幻覺

推理與行動交織：ReAct vs. Chain-of-Thought

Chain-of-Thought (單向黑盒)

  • 模式：`Input` $\to$ `Thinking (Tokens)` $\to$ `Answer`
  • 致命弱點：所有推導均在閉合參數內部完成，一旦進入未知領域便開始憑空編造。
  • 實測幻覺率：在 HotpotQA 多跳問答中高達 56%！

ReAct (推理與行動交織)

  • 模式：`Thought` $\to$ `Action` $\to$ `Observation` $\to$ `Thought`
  • 架構防護：每一次思考均建立在客觀工具返回的真實觀察之上，強制接地（Grounding）。
  • 實測幻覺率：直接將客觀事實幻覺壓制為 0%！

史丹佛課堂思辨

高難度交鋒：推理錯誤 47% vs. 幻覺 0% 之謎

學生尖銳提問 (00:37:46)：「既然 ReAct 的推理錯誤（Reasoning Error）依然高達 47%，為什麼同張表格裡的幻覺（Hallucination）卻是 0%？推論出錯難道不算幻覺嗎？」

客觀事實幻覺 (Hallucination = 0%)

定義：憑空捏造現實中不存在的事實、文獻、人名或 API 返回值。
ReAct 為何為 0：每一步思考嚴格依賴外部檢索輸入（Observation），不允許自行編造資料源，因而杜絕事實捏造。

邏輯推論錯誤 (Reasoning Error = 47%)

定義：面對客觀真實的輸入，模型產生了邏輯謬誤、搜尋循環或推導偏差。
為何依然高達 47%：模型雖然看到了真實內容，但可能錯誤解讀資訊、提出無效的查詢關鍵字，或無法從空搜尋中復原。

工程管線

工具調用解剖學四步流水線 (Anatomy of a Call)

1. Select (選擇)

意圖匹配：從 Context 註冊的 Schema 清單中挑選目標工具。

範例：`read_file`

2. Arguments (參數)

參數提取：將上下文意圖填入強型別欄位。

範例：`{"path": "test.py"}`

3. Validate (驗證)

確定性校驗：在發出請求前進行 Schema 型別與邊界約束檢查。

範例：`path: string`

4. Execute (執行)

沙盒隔離：於完全隔離環境中運行，結果注入 Context。

範例：`def add(a, b): ...`

工程核心要義：缺少 Validate 與 Sandbox，代理系統將立即面臨命令注入、路徑遍歷或主機崩潰的致命風險。

出席章節：II. 工具調用解剖學四步管線 (Figure 4)
除錯體系

代理工程三層架構體系 (Agents: The Three Layers)

系統層 (The System)

  • 認知架構設計：ReAct 狀態機、多代理通訊拓撲。
  • 防護欄與排程：確定性 Checkpoints、沙盒超時控制。
  • 記憶管理：滾動摘要壓縮與快取機制。

資料層 (The Data)

  • 示範案例 (Few-shot)：高品質軌跡示範、上下文調優。
  • 介面文件：精確的工具描述與 Schema 邊界說明。
  • 訓練與對齊：專家軌跡微調與偏好對齊數據。

評估層 (The Evals)

  • 真實基準測試：SWE-bench（代碼修復）、WebArena（網頁導覽）。
  • 端到端指標：任務解決率（Pass@1）、單步成本、執行時長。
  • 故障診斷：軌跡錯誤回溯與漂移偵測。

安全與邊界

真實世界事故案例：OpenAI Operator 買牛奶危機

事故病理解析 (2025.01 實例)

  • 指令模糊：使用者輸入「幫我買生活用品/牛奶」。
  • 無意圖校準：未確認住址與偏好超市，直接自主開啟 Instacart。
  • 隨機下單：自動定位到愛荷華州隨機超市開始加購。
  • 風險本質：代理掌握真實信用卡與網路權限，全自動黑箱盲跑引發經濟損失。

工業級確定性防護解方

  • 只讀操作全自動：搜尋、讀取檔案允許 Agent 自由迭代。
  • 寫入操作加防護：代碼修改需經過本機 Linter/CI 確定性驗證。
  • 實體與資金操作強制中斷：凡涉及付款、刪庫、實體物流，強制中斷並等待人類 Explicit Approval（確認門檻）！

終局思考

軟體工程代理的終局與最佳實踐

核心驅動力：測試時計算

  • SWE-bench Verified 準確率一年內從 30% 躍升至 80%+。
  • 能力倍增的主因不是單純模型參數量放大，而是「代理工作流 + 測試時多輪反思（Test-time Compute）」的爆發。

工程師的唯一出路

  • 停止盲目微調 Prompt，全面轉向構建確定性認知架構（Cognitive Architecture）。
  • 以「系統層、資料層、評估層」為錨點，將代理緊密鎖定在可測試、可驗證的軟體工程防護欄之內！

「未來的軟體架構師，不再是逐行代碼的編寫者，而是指揮無數專業代理協同作業的系統架構總工程師。」
